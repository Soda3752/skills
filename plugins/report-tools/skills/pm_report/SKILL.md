# PM Report — 技術調查報告產生 Skill

## 目標

將對話中已完成的調查或分析結果，整理成一份符合以下規範的繁體中文技術報告：

- **語言**：全繁體中文，技術術語保留英文原名（如 API、GPS、CMMotionManager），但程式碼識別字（變數、函式、參數）一律翻譯為中文描述
- **格式**：Markdown，流程圖使用 Mermaid
- **儲存位置**：當前工作目錄的 `.claude/report/YYYY_MM_DD/` 資料夾（日期為今日）
- **檔名**：以報告主題命名，例如 `GPS位置上傳業務邏輯調查報告.md`

---

## 步驟一：確認調查內容

從當前對話中擷取以下資訊（不要問使用者，從上下文中自行整理）：

1. **調查主題**：這次在調查什麼？
2. **涉及的程式碼範圍**：哪些檔案、哪些函式/類別？
3. **核心結論**：最終答案是什麼？
4. **各層機制**：有哪些關鍵邏輯層？每層如何運作？
5. **參數與常數**：關鍵數值是多少？
6. **風險與邊界情境**：有哪些已知的邊界案例或潛在問題？

若對話中的資訊不完整，先閱讀相關程式碼補齊，再進行下一步。

---

## 步驟二：準備儲存位置

```bash
# 取得今日日期（格式：YYYY_MM_DD）
# 在當前工作目錄下建立報告資料夾
mkdir -p .claude/report/$(date +%Y_%m_%d)
```

## 步驟四：英文識別字翻譯規則

撰寫報告時，對程式碼中的識別字（變數、函式、參數、屬性）一律轉換為中文描述：

| 翻譯原則 | 範例 |
|---------|------|
| 布林旗標 → 「是否 + 動詞」 | `isCurrentlyMoving` → 是否正在移動中 |
| 數值門檻 → 「X 上/下限」 | `accuracyLimit` → 精度上限 |
| 計數器 → 「X 計數」或「X 次數」 | `failThreshold` → 失敗次數門檻 |
| 函式名 → 動詞片語 | `uploadLocation()` → 位置上傳函式 |
| 通知名稱 → 「X 通知」 | `stopMoving` → 停止移動通知 |
| 佇列/執行緒 → 描述其用途 | `DispatchQueue.sync` → 序列同步隊列 |
| 系統 API 屬性 → 中文意義 | `distanceFilter` → 距離篩選器 |
| 技術名詞（如 race condition）→ 中文 | → 競態條件 |

**例外：不翻譯的內容**
- 類別名稱（`CLLocationManager`、`CMMotionManager`）
- API 路徑字串（`api/upload/location`）
- 業界通用縮寫（GPS、API、UI、HTTP、JSON）
- 程式語言關鍵字

---

## 步驟五：Mermaid 流程圖規範

- `flowchart TD`：主業務流程，覆蓋所有主要分支
- `stateDiagram-v2`：狀態機（如有移動/靜止、開啟/關閉的狀態轉換）
- 節點文字**全部使用繁體中文**
- 決策節點（菱形）必須明確標示條件，不可含糊
- 有換行需求一律透過 "</br>" 進行換行 而非 "\n"
---

## 步驟六：儲存報告

將完整 Markdown 內容存入：

```
.claude/report/YYYY_MM_DD/{主題}報告.md
```

儲存完成後，告知使用者報告路徑，並提供**一段摘要**（2-3 句話），說明報告的核心結論與章節數量。

## 品質檢查清單

存檔前確認以下項目均已完成：

- [ ] 結論摘要清晰，不迴避直接回答
- [ ] 所有 Mermaid 流程圖節點均為繁體中文
- [ ] 無任何英文變數名出現在正文表格或說明文字中
- [ ] 風險區塊至少包含 2 個真實邊界情境
- [ ] 報告儲存於正確的日期資料夾
