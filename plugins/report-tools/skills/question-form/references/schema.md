# 問題 JSON 格式與寫法

## 完整範例

```json
{
  "title": "會員系統規格確認",
  "intro": "共 6 題。有推薦標籤的是我的建議，不確定就選它。",
  "questions": [
    {
      "header": "登入方式",
      "question": "會員要用什麼方式登入？",
      "context": "目前只有 email + 密碼，PM 提過要加社群登入。",
      "multi": true,
      "options": [
        {
          "label": "Email + 密碼",
          "desc": "保留現有流程",
          "effect": "不用改後端，沿用現有忘記密碼流程",
          "cost": "註冊轉換率最低",
          "recommended": true
        },
        {
          "label": "Google 登入",
          "desc": "接 Google OAuth",
          "effect": "多一顆按鈕，一鍵註冊",
          "cost": "要申請 OAuth client，約多 1 天；帳號合併邏輯要另外設計"
        }
      ],
      "placeholder": "例如：還要 Apple 登入"
    },
    {
      "header": "命名",
      "question": "這個功能在 UI 上叫什麼？",
      "options": []
    }
  ]
}
```

## 欄位

| 欄位 | 必填 | 說明 |
|---|---|---|
| `title` | 建議 | 頁面標題，也會出現在複製結果第一行 |
| `intro` | 否 | 標題下的一段說明，支援換行 |
| `questions[].question` | 是 | 題目本身，一句話問清楚 |
| `questions[].header` | 建議 | 2～6 字的主題標籤，例如「登入方式」，複製結果會帶上 |
| `questions[].context` | 否 | 為什麼要問這題、目前狀況 |
| `questions[].multi` | 否 | `true` = 複選（checkbox），預設單選 |
| `questions[].options` | 否 | 空陣列或省略 = 純輸入題 |
| `questions[].placeholder` | 否 | 輸入框提示文字 |
| `options[].label` | 是 | 選項名稱，短 |
| `options[].desc` | 建議 | 這個選項是什麼 |
| `options[].effect` | **應填** | 選了之後 Claude 會怎麼做、系統會變成什麼樣 |
| `options[].cost` | **應填** | 選它要付出什麼：時間、複雜度、失去的彈性、風險 |
| `options[].recommended` | 每題一個 | 推薦選項，顯示「推薦」標籤 |

選項字母 A、B、C⋯ 由頁面自動依順序編上，不要寫進 `label`。
每題底下一律有輸入框，使用者可以補充或寫「都不是」的答案，不用另外加「其他」選項。

## effect／cost 怎麼寫

寫「選了會發生什麼」，不是重述選項名稱。

| | 壞 | 好 |
|---|---|---|
| effect | 使用 Redis 快取 | 列表 API 從約 800ms 降到約 50ms；我會新增 `CacheRepository` 並在 Koin 註冊 |
| cost | 比較複雜 | 多一個要部署的服務；資料改了要處理快取失效，漏掉就會看到舊資料 |
| effect | 比較好 | 之後加新語系只要多一個 strings 檔，不用動程式 |
| cost | 無 | 沒有額外成本，但現有 3 個畫面要改寫，約 30 分鐘 |

原則：

1. **具體到可以驗證**：數字、檔名、會動到的畫面數、大約時間。
2. **cost 不能寫「無」了事**。真的沒代價就寫「幾乎沒有，唯一差別是 X」。每個選項都有被放棄的東西。
3. **推薦選項的 cost 也要誠實寫**，不能因為是推薦就淡化。
4. **選項之間要互斥**（單選題）。兩個選項可以同時成立就改成複選。

## 複製結果長這樣

使用者按「複製所有答案」後貼回來的文字：

```
# 會員系統規格確認 — 作答結果

Q1【登入方式】 會員要用什麼方式登入？（複選）
答：A Email + 密碼、B Google 登入
補充：還要 Apple 登入

Q2【命名】 這個功能在 UI 上叫什麼？
答：（未作答）

※ 尚有 1 題未作答，請 Claude 自行判斷或採用推薦選項。
```

解析規則：

- `答：A xxx` → 選了該選項；複選以「、」分隔。
- `答：（未選選項，見補充）` + `補充：` → 使用者不滿意任何選項，以補充文字為準。
- `答：（未作答）` → 用推薦選項，並在回覆中明講「Qn 沒答，我採用推薦的 X」。
